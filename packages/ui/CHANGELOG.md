# @uisatin/ui

## 1.0.0

### Minor Changes

- 40e51cc: Agent suggestion: new part `AgentSuggestionChangeValue`, one change's value as `AgentSuggestionChanges` draws it (the old value struck through, an arrow, the new one), for a row of your own with its own controls. `AgentSuggestionChanges` renders through it and looks the same.
- 5f3af4a: Stroke widths by one rule, interactive → strong, surfaces → default. New tokens `border-width/strong` (1px, `--sa-border-width-strong`) for the edge of anything you click, press, type into, toggle or drag (buttons in every variant and their rings, chips, toggles, segmented controls, attachment chips, drop zones, fields, Checkbox, Radio, Selectable cards, the Slider thumb) and `border-width/default` (0.75px, `--sa-border-width-default`) for surfaces and decoration (cards, popovers and menus, dialogs, sheets, toasts, tables, separators, badges, Kbd, code blocks). The default is written in CSS as what browsers draw for 0.75px (1px on 1x screens, 0.5px on 2x, 0.667px on 3x) so box-shadow strokes are as crisp as borders. Focus rings and error edges keep their widths. `cn()` knows `border-strong` is a width, so it no longer drops it next to a border colour.
- 2f7919d: Calendar: `isDisabled(date)` rules out days besides `min`/`max` (weekends, booked days), and `renderDay(date, state)` draws each day: return the new `CalendarDay` part, the default day button, with your own children, `aria-label` or a Tooltip around it. `state` says whether the day is today, picked, in a range, disabled, from another month or holding the focus, and gives its full date. DatePicker, DateRangePicker and their panels pass both on to their Calendar. Days that can't be picked now have `aria-disabled` instead of `disabled`: they look the same (with the focus on one, its number is muted instead of faded, so the ring keeps its 3:1), but the arrow keys reach them and screen readers hear them as unavailable, instead of focus stalling on the day before. A DatePicker preset whose day `isDisabled` rules out is off, like the day.
- c5cd414: `CharacterCount`, exported from `@uisatin/ui/textarea`: the counter under Textarea, for a field of your own. With `max` it reads "134/120", with "Characters used:" before it for screen readers, and turns text/destructive once the count is over; without `max` it says "948 characters", the new `characterCount(count, formatted)` label, with the number written in `dateLocale`. Textarea renders its counter through it, so a Textarea's counter is now red too while the text is over `maxLength`.
- 37ac873: ChartTooltip: `rows` and `note` draw it as a card instead of the pill: the label muted on top (left out when null), a row per series (the legend's 8px dot in its colour, its name, its value at the end) and a muted note under them. `ChartTooltipRow` is exported.
- 2920919: Charts: the tooltip glides after the pointer. In Line, Area, Bar and Channel charts, moving across the points (or bars, or segments) no longer jumps the tooltip from one to the next: it chases the hovered point on a critically damped spring that settles in about 200 ms, with the Line chart's dot and drop line, and catches up smoothly when the pointer moves fast. Transform only; it jumps on the keyboard and under reduced motion, and the x label and the live text change at once. For custom charts: `useGlide(point, { measure, apply, immediate })`, `glideTransform` and `glideAnchor` from `@uisatin/ui/chart`, `ChartTooltip`'s `updateRef`, and `Floating`'s `updateRef`, which moves the layer within the frame for an anchor moved by a transform.
- 3bf35b3: ChartTooltip takes `stacked`: the label on one line and the value under it, for a value too long to share a line.
- 785854d: Combobox: `creatable` ends the list with a `Create "…"` row while the query matches no option exactly, and `onCreate` makes the option (or a promise of it), which is then picked. The row shows a Spinner while it waits and says so under it if it fails. New labels `createOption` and `createFailed`.
- 072d4cf: Combobox takes titled groups (`options={[{ label, options }]}`, as Select does): each is a `group` named by its header, and a group the query empties is left out. For a list the app searches itself: `filter={false}` lists `options` as given (or pass your own `(option, query) => boolean`), `onQueryChange` gets the query, `loading` puts a Spinner in the search row and marks the list `aria-busy` (with `loadingText` while nothing is listed), and `selectedOptions` keeps the chips of picks the current results don't hold. `renderOption` draws a row's content and `renderValue` the picks in the field. Clear now gives focus back to the field instead of dropping it, and "No results" sits outside the listbox in a `status` region, so screen readers hear it and the empty list no longer fails axe's required-children rule.
- 45277ac: CommandMenu: slots for a menu that changes what it shows. `query` / `onQueryChange` control the search (it is now emptied as the menu closes rather than as it opens, so a query set while closed is the one it opens with); an item with `keepOpen` runs without closing the menu; `header` goes above the search row, `children` take the list's place (the search then stops pointing at a list) and `footer` replaces the key hints. The highlight goes back to the first row whenever the rows change, not only when the query does, so a new set of rows never opens with a stale highlight. Satin Pro's CommandPages is built on these.
- 083c262: Dark surfaces lose their blue cast at the same lightness: `bg/canvas` #09090A, `bg/card` #121213, `bg/field` #1A1A1B, `bg/popover` #222223, `bg/muted`, `bg/hover`, `action/secondary/bg` and `status/neutral/bg` #272728, `bg/selected` and `border/default` #2F2F31, `border/subtle` #262628 (new primitives `--sa-color-canvas-dark` and `--sa-color-muted-dark`; Light is unchanged). Menus, popovers, the Attachment preview, Toast and the Bulk action bar get a soft, wide shadow in Dark (new `--sa-effect-shadow-float`, black 40% at 0 2px 20px) in place of the tight band, and keep their shadow in Light (`--sa-effect-shadow-float-contact`). They no longer read `--sa-effect-shadow-sm`, so an app that restyled menu shadows through it should set the two new variables instead.
- 9bcbecc: DatePicker, DateRangePicker and their panels take `presets`: a listbox of shortcuts before the calendar, at its side where both fit and above it where they don't (in a popover, the room beside the trigger decides). `datePresets` holds `today`, `tomorrow`, `nextWeek`, `last7Days`, `last30Days` and `thisQuarter`, worded through new SatinLabels keys (`presets`, `presetToday`…). Picking a preset moves the calendar to its month; a range still waits for Apply.

  The week now starts on the `dateLocale` label's first day (Sunday in en-US, Monday in pl-PL), for the calendar and for Next week; `weekStartsOn` pins it (`weekStartsOn={1}` keeps Monday). After the month arrows turn the month, a day in view stays reachable with Tab.

- 4718bf6: DecisionCard takes steps of your own: `children` take the answers' place and move with the step, `footer` takes Skip and Continue's place in the same row, and `previousStepLabel` and `nextStepLabel` name the step buttons ("Previous question" and "Next question" by default). A part that reads the same on both steps, such as a title every step shares, now stays still while the rest slides. A `ref` on the card no longer replaces the one the step slide measures with.
- a5e7565: Dropdown: `DropdownMenuItem`, `DropdownMenuCheckboxItem` and `DropdownMenuRadioItem` take `renderLabel`, which draws the label another way, as a Badge for example. `label` still names the row and drives typeahead.
- e7d16f1: DropdownMenu: submenus (`DropdownMenuSub`, `DropdownMenuSubTrigger`, `DropdownMenuSubContent`) and checkable rows (`DropdownMenuCheckboxItem`, `DropdownMenuRadioGroup`, `DropdownMenuRadioItem`), controlled or not. A submenu fades in from 4px on the side it opens. The menu now reads its direction from the trigger (or a new `dir` prop), so right to left ← opens a submenu and the panel is laid out right to left; a group with a header is named by it.
- f101a47: FileUpload: `media` shows your own picture in place of the upload mark above the title (an app's illustration of what the upload does), as List's `media` replaces its icon tile. The title still swaps to `dropTitle` while files are dragged over.
- 2790185: InputOTP: `onResend` adds "Didn’t get it?" under the cells with a resend that opens after a countdown (`resendAfter`, 30 s by default) and starts it again once the code is sent. `suggestion` offers a code that arrived by text in a popover under the cells ("428 193 From Messages"); choosing it fills the cells. A code that arrives at once (the suggestion, a paste, the browser's autofill) rolls into the cells like slot-machine reels, one cell after another. New labels `didntGetCode`, `resendCode`, `resendIn`, `useCode`, `fromMessages` and `codeReceived`, and `component/input-otp/suggestion-*` tokens for the popover: a dark chip in both themes, pressed like a Button, with a Messages mark drawn in small squares.
- fee5441: `SatinLabelSet` is an interface, so a package built on Satin (Satin Pro) adds its own words to it and one `SatinLabels` translates them all. A toast action's `label` and `altText` can be functions of the labels in effect under the Toaster (`(labels) => labels.cancel`), so code that calls `toast()` outside React still speaks the app's language. New type `ToastText`.
- a294604: LineCard and AreaCard take `labelEvery`: show every nth x label, counted back from the last point (3 shows every third month of a year). Left out, about seven labels spread across the plot, as before.
- 26a9f3f: Line chart exports `smoothPath(points)`, the monotone curve its line is drawn with, so custom charts and sparklines draw the same line.
- df56aec: Mention: `avatar` and `name` add a preview. Hovering or focusing the mention opens a Tooltip with the person's avatar (20px, hidden from screen readers) and full name (`name`, `label` by default); the mention becomes a tab stop with the focus ring, an outline 2px off. Without either prop it renders as before.
- 55a1e36: MessageActions: like, dislike and copy carry a Tooltip with their name. Copy confirms itself: for 1.5 s its icon turns to a check, its tooltip says "Copied" and a polite live region says it to screen readers.
- a2fe6ac: Motion: a new token, `--ease-spring`, a short damped spring (about 3% overshoot) written as a CSS `linear()` curve. MOTION.md keeps it for one thing, a dragged card dropping into its place; everything else still eases without overshoot.
- 5598f68: PromptBar `notice`: a Banner or an Alert inside the bar, above the field, 8px from its edges; the bar takes radius 20 with it in either shape. Banner `layout="inline"` fills its container on one row (10 × 4 padding, 13/18 title) with its own mesh glow, and a new `icon` puts a 16px mark before the title. Alert `layout="inline"` is one centred row with 12px padding, a 14/21 title and the 28px close button.
- 216b314: PromptMentionsMenu: `heading` (default true) shows or hides the Mentions / Commands group header. Rich text editor turns it off next to the caret; PromptBar keeps it.
- 7ce7b5a: Prompt mentions, for fields that aren't a textarea. `usePromptMenuState({ query, mentions, commands, disabled })` is the menu's state on its own: the host finds the trigger in its text and passes `{ kind, trigger, text, start }`; the hook searches (dropping a slow answer for an older query), filters and sorts commands, keeps the highlight, stays shut after Escape until the trigger changes, and says the number of suggestions in the status region. It returns `open`, `listed`, `items`, `index`, `current`, `move(±1)`, `highlight(i)`, `dismiss()`, `release(query)`, `announce(text)`, `listId`, `activeId` and `menuProps`. `PromptMentionsMenu` is the menu by itself (status region, group label, listbox, "No results", ↑↓ ↵ hints), anchored to `anchorRef` or a `virtualAnchor` rect, with `side`, `align`, `sideOffset` and `matchAnchorWidth` (false gives a fixed 288px). `usePromptMentions` and PromptBar are built on both and behave as before. `Mention` shows a mention outside a field, "@Tara Mendes" on a mention token's fill (status/brand-bg, a status/brand-border edge, radius-sm, medium text); its look is plain CSS on `[data-slot="mention"]`, so an editor that renders the same span without React gets it too.
- 16e24d3: PromptBar takes `mentions` (`{ trigger, search(query) }`) and `commands` (`[{ name, description, icon, run }]`): `@` and `/` open a menu above the bar, and a pick goes into the text as a token ("@Tara Mendes", "/schedule"), set in medium like the menu's labels, that the caret steps over and Backspace removes whole. `value` and `defaultValue` also take a `PromptValue` (`{ text, mentions, command }`), which `onValueChange` and `onSubmit` now pass as an extra argument; a message whose command has `run` goes to `run` with its arguments. No menu opens while an input method composes. New entry `@uisatin/ui/prompt-mentions` (`usePromptMentions`, `promptValue`, the types) and labels `mentions`, `suggestionsCount`, `tokenAdded`, `tokenRemoved`. PromptBar without the new props is unchanged.
- 1236f2b: RelativeTime (`@uisatin/ui/relative-time`), new: when something happened, in a `<time dateTime>` (`data-slot="relative-time"`, muted 13px, tabular figures). Relative today ("now", "5 min ago", "2 hr ago"), the clock time before that, and with `withDate` the date too ("Nov 16, 9:40 AM", with the year when it isn't this one). English short units lose their dot; other languages keep their own spelling; words and formats follow `dateLocale` in SatinLabels. Screen readers hear the full date and time from a visually hidden span, the short text is `aria-hidden`. Every time on the page reads one clock that ticks every 30 seconds while any listens and stops when none does, and a tick renders only the times whose text changed. `at` takes a Date, an ISO string or a timestamp; other props, `ref` included, go to the `time`. Also exported: `useRelativeClock(text)`, a text of your own from the same clock, and `dateTimeFormat` / `relativeTimeFormat`, shared `Intl` formatters built once per locale and options.
- 644a479: Stepper (`@uisatin/ui/stepper`): where a multi-step flow is, as an ordered list of steps with a number, a label and a description, joined by connectors. Steps are upcoming, current, complete (a check), error (an exclamation mark) or disabled. Linear by default (the steps before the current one are complete, none clickable); with `linear={false}` each step is a button that sets `value`. Horizontal or vertical, where the current step's content opens under its label (`StepperItem` children). A horizontal stepper narrower than 120px a step shows "Step 3 of 4" over a Progress bar, from a container query, so nothing shifts on load (`layout`). When a step completes its connector fills and the check fades in; right to left it mirrors. New words in SatinLabels: `stepOf`, `stepCompleted`, `stepError`.
- d6e2a07: Table: `empty` fills the body while `rows` is empty (an EmptyState, say) in one row across every column. Its content is as wide as the visible part of the table and centred there, so with `overflow="scroll"` it stays in view however far the columns scroll. The header stays.
- 526b5b7: Table: `footer` puts rows of your own in a `<tfoot>` under the body (a totals row), and `tableProps` reaches the `<table>` element itself, for a `role` such as `"treegrid"` or `aria-*`. Other props still go to the frame.
- a528e12: Textarea: `onChange` gets the change event after the text, `(value, event)`, for code that needs the caret or the input method's state; the old one-argument handlers still work. New `underlay`, drawn under the text inside the field and not clipped: pass `usePromptMentions().overlay` with its `textareaProps` on the field and a Satin Textarea takes @mentions as PromptBar does. With an underlay the field's fill moves to an `aria-hidden` layer of its own (`data-slot="textarea-fill"`, bg/field, bg/muted when disabled) under it and the textarea turns transparent; border, hover, focus ring, error and shadow stay on the textarea. Without one the markup is unchanged. usePromptMentions now also re-measures its token layer when the textarea is resized (the grip dragged, the box narrowed), not only when it renders.
- 6b6b29b: Time picker (`@uisatin/ui/time-picker`): `TimePicker` reads a typed time ("930", "9:30pm", "1430", the locale's AM/PM words) or picks one from a list every `step` minutes, with `min`, `max` and `isTimeDisabled` dimming what can't be picked; its value is `{ hours, minutes }`. `DateTimePicker` opens the Calendar with a column of times beside it; a pick sets the value and leaves it open until Escape, a press outside, or Enter on the picked time. Times are pills, the picked one filled like the Calendar's picked day. `TimeList` and `DateTimePickerPanel` are the list and the panel on their own; `parseTime` and `formatTime` are exported. 12 or 24 hours follow the `dateLocale` label unless `format` says otherwise. New words in SatinLabels: `time`, `showTimes`, `pickDateTime`, `timeHint`, `timeInvalid`, `timeUnavailable`.
- 5b5178f: Toast: `details` (on `toast()` options and on `<Toast>`) goes under the row, lined up with the title and running to the card's end, for a list of what a batch changed or a progress bar; the icon tile and the buttons stay beside the title, and the stack follows the toast's new height.
- 925d46a: Toast: `onClose(reason)` on toast() options is called once, as the toast starts to leave, with why: `'action'` (its action button), `'close'` (the close button, Escape, a swipe, `toast.dismiss`, or a new toast shown under the same `id`, which replaces it) or `'expire'` (its time ran out, pauses included). It's the way to commit something when an Undo window ends without a timer of your own that would drift from the toast's: hide the item at once, delete it for real unless the reason is `'action'`. With no `<Toaster />` mounted, toast() warns and calls `onClose('expire')` on the next microtask, after the caller's own state is set. New type `ToastCloseReason`.
- 8d1492b: Toast: `countdown` on toast() options draws a 2px bar along the bottom that drains over `duration`, so people see how long Undo stays. It pauses and goes on with the timer while the toasts are hovered or focused (or the window is in the background), keeps the card's size, is `aria-hidden` and is hidden under reduced motion. Toasts from toast() now keep their own time instead of Radix's, so updating one to `duration: Infinity` stops it for good.
- f938459: Tool call (`@uisatin/ui/tool-call`): one call an agent made to a tool, as a card of its own. The header is Thinking's tool step (icon, name, mono target) with the status: pending, running with the time so far, success with how long it took, error, cancelled; the status icons cross-fade. It opens onto the input and the output, as JSON in CodeBlocks or nodes of your own, cut at `maxLines` with Show all. A failed call opens on its own with the error and Retry. Parts: ToolCallRoot, ToolCallHeader, ToolCallContent, ToolCallSection, ToolCallError. New words in SatinLabels: `toolCallPending`, `toolCallRunning`, `toolCallDone`, `toolCallFailed`, `toolCallCancelled`, `toolCallInput`, `toolCallOutput`, `toolCallRetry`, `toolCallShowAll`, `toolCallShowLess`.
- 6314925: Toolbar (`@uisatin/ui/toolbar`): a row of controls that is one tab stop, on the Radix toolbar. Tab enters it once and leaves it; the arrow keys move between its items and wrap, Home and End jump to the ends, and right to left the arrows flip (the direction is read from the page). `ToolbarButton` is a tertiary Button and `ToolbarToggle` a ghost Toggle that stays pressed (`aria-pressed`, controlled or not), both at the toolbar's `size` (sm 28, md 32); with an `icon` and no children they are icon-only, named by `label`, which a tooltip shows with `shortcut` as keys. `ToolbarSeparator` is a rule between sets. `variant="floating"` puts the toolbar on the menu surface, for a bubble bar that `Floating` places over a text selection, and `preventFocusOnPress` keeps a press on an item from taking focus, so an editor keeps its selection. Name it with `aria-label`.
- ee4b2ed: Line heights are whole pixels. `text-sm` (13px) sits on a 20px line instead of 19.5px, and `text-2xl` (24px) on 32px instead of 31.2px, so text at these sizes is a little taller: a 10-line code block grows by 5px. On a half-pixel line every box of text ended on a half pixel, and an expander easing to that height dropped a pixel when it landed. The ratios in `--text-*--line-height` are now exact (`calc(16 / 11)` instead of 1.455), so `text-2xs` and `text-body-lg` land on 16px and 22px instead of 16.005px and 21.994px. This departs from the Figma kit's 13/19.5. Switch's label and description, and an Input group's add-ons, now set their own 20px and 21px lines.

## 0.6.0

### Minor Changes

- 0b7ebd0: Parts next to the props API, for layouts the props don't cover:

  - Dialog: `DialogRoot`, `DialogTrigger`, `DialogContent` (with `variant`, `closeButton`, `container`), `DialogHeader`, `DialogTitle`, `DialogDescription`, `DialogBody` and `DialogFooter` (with `start`). `Dialog` is now built from them, so both look and behave the same.
  - SegmentedControl: write the segments as `SegmentedControlSegment` children instead of `items`, when one needs more than a label and an icon.
  - Table: `renderCell` wraps or replaces every body cell's content (a link to the row), `renderRow` draws each row (`<tr {...rowProps}>{children}</tr>` with your own handler or attribute).

  SearchBar takes `ref` as a plain prop like every other component (it was the last `forwardRef`).

- 0b7ebd0: Every word a component says on its own now comes from `SatinLabels`, so an app can translate all of it. New in the set: the accessible names that wrap data (Remove and Preview of a file, Change in DecisionCard, Uploading and Cancel in FileUpload, Breadcrumb's Show N more, a line chart's point count, Pagination's pages and "Page 5 of 12", Table's scroll region), screen-reader text (Textarea's character count, CodeBlock's added and removed lines, DecisionCard's ranking moves) and the English defaults of props: AgentPicker's `createLabel` and `placeholder`, AgentLoading's and Thinking's `label`, Attachment's `openLabel`, AnnouncementBar's and Banner's `dismissLabel`, Breadcrumb's, Pagination's and CookieConsent's `aria-label`, Card's `closeLabel`, CookieConsent's message and buttons, DecisionCard's Skip, Continue and Rewrite, DonutCard's `centerLabel`, FileUpload's titles and rejection messages, Message's `thinkingLabel`, Pagination's Previous and Next, PromptBar's placeholder and + menu rows, CommandMenu's `emptyText` and Toaster's region name. A prop still wins over its label. Calendar and the date pickers name months and weekdays and write dates in the new `dateLocale` label (en-US by default), and `formatDate` and `formatRange` take a locale.

  Labels that wrap data are functions, so a translation puts the words in its own order: `removeItem`, `cancelItem`, `changeItem`, `previewOf`, `uploading`, `largerThan`, `sentOfTotal`, `showMore`, `noResultsFor`, `selectRow`, `selectNamedRow`, `tableRegion`, `codeRegion`, `chartPoints`, `positionOf`, `page` and `pageOf`. `pageOf` gets Pagination's animated number as a node, so write it with JSX.

  Table takes `rowLabel(row, index)`: each row's select checkbox then says "Select Acme Corp" instead of "Select row 3", which also stays true when the table is sorted.

  Breaking for apps that set `selectRow`: it is now a function `(row) => string` instead of the word Table put before the number, so a language can place the number where it belongs. Write `` selectRow: (n) => `Zaznacz wiersz ${n}`  `` instead of `selectRow: 'Zaznacz wiersz'`. SearchBar's placeholder is now the `search` label, "Search…" with an ellipsis like the other fields.

- 0b7ebd0: Every variable Satin declares is now `--sa-*`, the semantic tokens included: `--sa-bg-card`, `--sa-text-muted`, `--sa-border-default`, `--sa-action-primary-bg`, `--sa-status-*`, `--sa-component-*`, the control heights, and the variables components set inline (`--sa-code-plain` and the other CodeBlock colours). An app's own `--bg-card` or `--text-muted` no longer reaches Satin, and Satin's no longer lands on the app's `:root`. `themeCss()` writes the new names, and the stylesheet check now fails on any variable outside `--sa-*`.

  Breaking for CSS that reads or sets the old names. To read them for one more minor version, import `@uisatin/ui/compat.css` after `styles.css`: it aliases each old name to its `--sa-*` one, in Light, Dark and every tone, and goes away in 0.7. To change a token, set the `--sa-*` name (rename `--bg-card: …` to `--sa-bg-card: …`).

  Dark mode also follows `data-theme`: `data-theme="dark"` works like the `dark` class, and `data-theme="system"` follows the operating system's `prefers-color-scheme` with no script. `themeCss()` with a `scope` writes all three. The tokens themselves ship as `@uisatin/ui/tokens.json` (W3C design tokens, Light and Dark).

  The reduced-motion rule now stops only Satin's elements and what's inside them, in the base layer; it used to set every element on the page to a near-zero duration with an unlayered `!important`, the app's own animations included. InputOTP's caret blinks from its own `data-slot` rule.

  `@uisatin/ui/theme` (`themeCss`, `themeVars`) is no longer marked `'use client'`, so a Server Component can call `themeCss()`, e.g. in a Next.js root layout; import it from `@uisatin/ui/theme`, not the root entry, there. The Channel and Donut charts read their series colours from Satin's `--sa-chart-*` again: from npm they read the unprefixed `--chart-*`, so they lost their colours, or took an app's own shadcn chart colours.

- 0b7ebd0: Every component now works right to left. With `dir="rtl"` on `<html>`, spacing, corners, borders and text alignment mirror: Satin sets them with start and end (logical properties) instead of left and right. Button group, Split button and Input group join from the right with round outer corners; close buttons sit in the top-left corner; the Table's first column sticks on the right and its row outline, scroll fade and scroll bar follow; the user's Message bubble has its tail on the left; values in Select and the date picker start at the right.

  Arrows that mean next, previous or forward point the other way: Breadcrumb, Pagination, the date picker's months, Context menu's submenus, Sidebar groups, Decision card's steps, Announcement bar, Action button, Agent suggestion, and Link's and Attachment's open-elsewhere arrow (↖). Icons that aren't directional, such as close and check, stay.

  Switch shows on with its thumb on the left. Toaster sits in the bottom-left corner and swipes away to the left. In the date picker Left moves to the next day and Right to the one before; Page Up, Page Down, Home and End are unchanged. Pagination's numbers, Decision card's questions, Progress's indeterminate bar and Skeleton's shimmer move the right-to-left way, and Textarea's grip moves to the bottom-left corner, with the browser's resizer.
